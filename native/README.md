# The native shell

Everything the iPhone app needs that the web app does not. The app itself is
still the one in `src/`; this is the wrapper that puts it on a Home Screen as a
real app rather than a bookmark, signed with your own Apple developer account.

```
native/
  ios/    the Xcode project, generated by Capacitor
  www/    the web build the shell wraps, rebuilt on every sync (gitignored)
```

The Capacitor config lives at the repository root, because that is the only
place Capacitor will look for it. It points both of these paths back in here.

## Getting it onto your phone

```bash
npm install
npm run ios:open
```

That builds the app for the shell, copies it in, and opens Xcode. Then, once:

1. Select the **App** target, **Signing & Capabilities**
2. Tick **Automatically manage signing** and pick your **Team**
3. Change the **Bundle Identifier** if `com.gymapp.gym` is taken; anything of
   the form `com.yourname.gym` works

Plug the phone in, pick it from the device menu, and press Run. The first time,
the phone asks you to trust the developer under **Settings, General, VPN and
Device Management**.

A paid developer account signs the app for a year. A free one signs it for
seven days, after which the app stops opening until you run it from Xcode
again, so it is worth using the paid account you already have.

## After a code change

```bash
npm run ios          # rebuild and copy into the shell
```

Then press Run in Xcode. `npm run ios:open` does both and opens Xcode as well.

## What the shell adds

The web app already runs on iPhone; these are the things a browser cannot do,
and each one falls back to the web behaviour when the app is not in the shell.

- **Rest alerts that actually arrive.** In a browser nothing runs once the page
  is out of sight, so the alert can only be posted at the moment the timer ends
  and only lands if the page is still alive. Here the deadline is handed to iOS
  when rest starts and cancelled if you skip, so it reaches you in your pocket
- **The screen stays awake** through the system idle timer rather than a
  Screen Wake Lock the browser drops on every backgrounding
- **Real haptics.** Each kind gets the feel it was named for through the Taptic
  Engine, instead of the hidden-switch trick Safari needs
- **Your data is in the app's own container**, so clearing Safari cannot touch
  it and only deleting the app erases it
- **No service worker**, because the shell already ships the files. There is
  nothing to cache and no update to fetch, so `virtual:pwa-register` is aliased
  to a stub in this build and Workbox never enters the bundle

## Artwork

The app icon and launch image are drawn from the same source as everything
else, in `scripts/art.mjs`:

```bash
node scripts/ios-assets.mjs   # writes into ios/App/App/Assets.xcassets
```

It drives whatever Chrome the machine already has, so building the app needs no
extra npm dependency.

## A note on the lockfile

CI installs with `npm ci` on Node 20. Node 22 and later ship an npm whose
resolver hoists `vitest`'s nested esbuild to the top of the tree and drops the
`optional` flag on its platform binaries as it goes, which `npm ci` on Linux
then refuses. `.nvmrc` pins 20 for that reason. If you add a dependency on a
newer Node, regenerate the lockfile with the version CI uses:

```bash
npx npm@10 install --package-lock-only
```

No `@esbuild/*` entry should come out of that without `"optional": true`.

## Regenerating the project

`ios/` is checked in and meant to be edited: signing settings and anything else
you change in Xcode live there. If you ever need it back from scratch, delete
it, run `npx cap add ios`, then `node scripts/ios-assets.mjs` for the artwork
and set the portrait-only orientations in `Info.plist` again.
